cli · waverun the testbench, open its waveform in the browser

dewfpga wave

What does its help text say?

dewfpga wave [top|testbench|file.vcd] [--no-open]
                                 run the simulation and open its waveform in the browser, Vivado's wave window
                                 (sim records every signal; a .vcd given by name is opened as it is);
                                 dewfpga sim [top|testbench] --wave[=surfer|browser|both] [--no-open] opens it in
                                 Surfer (--wave), the browser page or both; --no-open writes it and opens nothing

From dewfpga --help, as bin/dewfpga prints it.

What does the README say?

dewfpga sim --wave runs the testbench, then opens what it recorded in Surfer, which dewfpga install puts in. --wave=browser opens it in a page in the browser instead, Vivado's wave window without Vivado, and --wave=both opens both. Both start with the testbench's own signals, the design under it to expand; the testbench's checking (an errors counter, exp_* and expected* values, the variable a for (int i ...) declares) is left out of that first view.

dewfpga sim --wave                  # the folder's one testbench, in Surfer
dewfpga sim tb_mux8 --wave=browser  # a testbench by name (or the design it tests: mux8), in the browser
dewfpga sim top_mux --wave=both     # Surfer and the browser
dewfpga wave tb_mux8.vcd            # a recording that is already there, in the browser

The last line of dewfpga sim top_mux --wave says what was simulated, with what, and where it opened: waveform: top_mux_tb.vcd, simulated by Icarus Verilog 13.0 (stable), opened in Surfer 0.7.0.

The testbench needs nothing added, as in Vivado: no $dumpfile, no $dumpvars, no $finish. dewfpga sim records every signal under the testbench into <testbench>.vcd (a testbench that calls $dumpvars itself keeps its own file). Testbenches may sit in a tb/ or sim/ folder beside the design, several in one file; each run starts at one of them (dewfpga tops --sim lists them). A testbench with a free-running clock and no $finish stops at 1000 ns, where Vivado's Run Simulation stops (SIM_TIME=10us runs it longer). Files without a `timescale get Vivado's 1ns/1ps. A testbench that reports errors still opens: the waveform is where the wrong value is found. A run that stops at a compile error opens nothing. --wave --no-open writes what the viewer would get and opens nothing.

dewfpga sim --wave[=browser|both]   simulate, then open the waveform in Surfer, the browser, or both
dewfpga wave [tb|file.vcd]          simulate if needed, then open the waveform in the browser

From the README.

Which errors can it stop with?

5 codes in the error catalog.

  • no-waveform: dewfpga wave was given a .vcd that is not there, or the simulation wrote none.
  • waveform-too-large: The .vcd is too large for the browser page; record a shorter run or fewer signals.
  • waveform-not-opened: The page was written, but there is no command to open it in a browser here.
  • wave-viewer-missing: dewfpga sim --wave opens the waveform in Surfer, and Surfer is not on this machine.
  • waveform-unreadable: The file given as the waveform is not a VCD the viewers can read, or it could not be read at all.
