One command from SystemVerilog to a Basys3

The by-hand setup, done for you. One line installs the chain; after that, dewfpga builds whatever .sv files are in the folder.

No Mac or no board with you? The Basys3 simulator and the testbench runner do the same first two steps in a browser, with nothing installed.

curl -fsSL https://nosey-dewdrop.github.io/dewfpga/install | bash   # ~4 min, 1.4 GB, once

Requirements: macOS on Apple Silicon and Homebrew (its installer brings Apple's Command Line Tools along; the CLI checks and says so if either is missing). It puts the CLI in ~/.dewfpga, links dewfpga into Homebrew's bin and runs dewfpga install. Re-run the same line to update. No Node needed.

CLI to Basys3: how to use the CLI?

  1. Homebrew. No brew yet? Run the one line on brew.sh, paste the lines it prints under "Next steps", open a new terminal window. It installs Apple's Command Line Tools on the way.
  2. The chain. Paste the curl ... | bash line above. About four minutes; it ends with dewfpga check printing all good. A red line instead names the missing piece: run the same line again, it skips what is done.
  3. A project. dewfpga new blink && cd blink gives you the blinking LED: blink.sv, blink_tb.sv, blink.xdc, a VS Code task. Your own lab goes the same way: the .sv files and the .xdc in one folder.
  4. Simulate, build. dewfpga sim runs the testbench; dewfpga bit turns the .sv into blink.bit. An error is one line, file:line: ERROR [code], with the fix and its page.
  5. The board. Plug the Basys3 into the PROG port, switch it on, dewfpga flash. It builds first when the .bit is older than the .sv. The LED blinks.

How do you use it?

In any folder with blink.sv and blink.xdc:

dewfpga sim      # iverilog
dewfpga bit      # .sv -> .bit   (4.6 s)
dewfpga flash    # program the board: the LED blinks

For an existing lab, keep the design's .sv/.v files and pin file in one folder and run the commands there. Submodules can live in separate files. The top comes from the module hierarchy; a uniquely matching .xdc can select among candidates, and the CLI prints that choice. Otherwise it stops and asks you to name the module: dewfpga flash <top>. File names alone never silently choose the top.

A testbench is a module without ports that instantiates the design. A $finish or $stop in a design module is reported as an error, not used to reclassify it as a testbench. Files containing only packages, interfaces or typedefs are still a CLI limitation; see the guide's limits. The course's seven-segment source can be repaired automatically; a Vivado-generated simulation netlist is rejected with an explanation.

Already using Vivado? Run inside the folder containing your .xpr or its .srcs subfolders. The active project sets and top are used; output files land at the project root. dewfpga tops lists candidates without writing files. For editor tasks and the top chooser, run dewfpga vscode; see VS Code setup.

What does an error look like?

When sim, bit or flash stops, it prints one line in one format, file:line: ERROR [code]: message, then the fix and the address of that code's page. Every code, with what you saw, why, the fix and an example: the error catalog.

Commands

dewfpga install                     install the toolchain (safe to re-run)
dewfpga check                       is every piece in place
dewfpga sim|bit|flash|clean [top]   build a flat folder or a Vivado project
dewfpga tops                        list top candidates without writing files
dewfpga vscode [--remove]           set up or remove the editor integration
dewfpga new <dir>                   blink example with a VS Code task (⌘⇧B = flash)
dewfpga uninstall                   remove what install built in ~/fpga, the CLI and its link (your files and brew packages stay)
dewfpga --version

Scope

  • Board: Digilent Basys3 (XC7A35T-1CPG236C). Other 7-series boards: change DEVICE in install.sh, PART and CHIPDB in the Makefile and the openFPGALoader board name, then regenerate the chipdb; untested.
  • Platform: macOS arm64. Intel Mac and Linux are untested and refused by the script.
  • The course's XDC files work as-is (PACKAGE_PIN + IOSTANDARD).
  • flash writes SRAM: the design is gone after a power cycle.
