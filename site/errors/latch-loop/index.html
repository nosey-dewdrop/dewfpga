Why does it happen?

Since #4 the CLI makes yosys build an inferred latch as Vivado does (the latch warning). When the netlist still holds the value in a loop of LUTs instead of a latch cell (a shape the readers keep as logic), the board would glitch, so this is an error.

What is the fix?

Assign the signal on every path, or say latch when you mean it:

always_latch if (en) q <= d;
