dewfpga

Write SystemVerilog on an Apple Silicon Mac and flash a Digilent Basys3. No Vivado, no virtual machine.

Docs

CS223_Mac_Setup.pdf ↗ · step by step, from opening the terminal to an LED blinking on the board. 13 pages.

CLI and the browser simulator: coming soon.

Use

In any folder with blink.sv and blink.xdc:

dewfpga sim      # simulate (iverilog)
dewfpga bit      # .sv -> .bit, about 4 seconds
dewfpga flash    # program the board

No Makefile, no project layout. Every .sv in the folder is synthesized; the top module is the one with a matching .xdc. First time? dewfpga new blink gives you a blinking LED to start from.

What runs under the hood?

StageTool
simulationiverilog
synthesisyosys
place & routenextpnr-xilinx (built from source, pinned commit)
bitstreamprjxray fasm2frames + xc7frames2bit
chip databasegenerated for XC7A35T
programmingopenFPGALoader over USB-JTAG

Vivado does these jobs in one window. Five open-source tools do them here; the installer wires them together.

Why does this exist?

Vivado has no macOS build. Setting up the open-source chain by hand took six hours because of six walls nobody documents in one place:

  1. oss-cad-suite does not ship nextpnr-xilinx (497 MB downloaded to learn that).
  2. Apple clang has no OpenMP; nextpnr must be built with USE_OPENMP=OFF.
  3. PEP 668 blocks pip install into Homebrew Python; a venv is required.
  4. prjxray needs --recursive or its submodules are missing and cmake fails.
  5. cmake 4 rejects prjxray without CMAKE_POLICY_VERSION_MINIMUM=3.5.
  6. There is no prebuilt chip database; it has to be generated.

Scope

Basys3 (XC7A35T) on macOS Apple Silicon. Tested on an M2 with 8 GB and on GitHub's macOS runners. Intel Macs, Linux and other boards are not supported yet. flash writes SRAM, so the design is gone after a power cycle.
