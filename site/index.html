How does it work?

Vivado does five jobs for a CS223 lab. One open-source tool does each job here, and a small Makefile runs them in order.

your_design.sv
  |
  |-> Icarus Verilog   -> simulation
  |-> Yosys            -> synthesis
  |-> nextpnr-xilinx   -> place and route
  |-> fasm2frames      -> configuration frames
  |-> xc7frames2bit    -> your_design.bit
  `-> openFPGALoader   -> the board, over USB

Your .sv and .xdc files are the same ones Vivado reads. The course's pin files work as they are, once you uncomment the pins you use.

Why does this exist?

Vivado has no macOS build. Setting up the open-source chain by hand took six hours, because of six walls that nobody documents in one place: oss-cad-suite ships no nextpnr-xilinx, Apple's clang has no OpenMP, Homebrew's Python refuses pip install, prjxray hides its submodules, CMake 4 rejects prjxray, and there is no prebuilt chip database. The six walls, and what each one cost.

When a step fails, the error text is usually the fastest way in. Every error hit during this setup, with the fix.

What can it not do?

  • Nothing from Vivado's IP Catalog: no Block Design, MicroBlaze, AXI, Clocking Wizard or the BRAM, VGA and UART cores. 35 old CS223 repos and 240 source files were searched and none of them use any of it.
  • No waveform viewer, schematic or in-chip debugger. make sim writes a .vcd file and stops there.
  • Only the Basys3 (XC7A35T), only Apple Silicon. Intel Macs, Linux and other boards are untested.
  • The tools are unofficial. AMD does not make or support them. What you should be concerned about.
